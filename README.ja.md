# openVGCengine

[English](README.md) | **日本語**

VGCの対戦エンジンと、そのエンジン上で自己対戦を重ねてVGCを学んだニューラルネットワーク、そしてその2つを使うデスクトップツール集です。
チームを仮想敵と戦わせて試す、マッチアップや選出を研究する、リプレイを振り返る、自分のPC上でボットと練習する、といったことができます。

## 中身

| 構成 | 内容 |
|---|---|
| **エンジン**（`crates/`） | Rust製の対戦シミュレーター。[Showdown](https://github.com/smogon/pokemon-showdown)のシミュレーターの移植で、1戦ごとにShowdownと照合しています（同じ乱数で、すべてのステップが同じ結果になること）。速度重視の設計で、モデルはこのエンジン上で膨大な数の対戦をこなして学習しました。 |
| **モデル**（`trainer/`。重みは[Releasesページ](https://github.com/HibikiDev/openVGCengine/releases)） | 対戦するニューラルネットワーク。選出する4体、初手、毎ターンの技と交代を選びます。 |
| **ツール**（`suite/`） | モデルを使うデスクトップアプリ：チームのテスト、マッチアップ・選出の分析、リプレイの振り返り。 |
| **練習相手** | 自分のPC上で動くShowdownサーバーで、ボットと練習できます。 |

**対応ルール。** VGC 2013以降、ShowdownにあるすべてのVGCルール（第5〜8世代、スカーレット・バイオレットの各レギュレーション、
Champions）。ただしChampionsのReg M-AとM-Bは未対応です。すべてのツールと練習相手が全ルールに対応しています（「ルール」欄で選びます。
初期値は現行レギュレーションの **Champions VGC 2026 Reg M-C**）。クローズドチームシートのルール（VGC 2013〜2022）には
「チームシート」の切り替えがあります：クローズド（実際のルール通り）か、OTSの情報を使うオープンか。

## モデル

**どう学んだか。** 対戦を通じてです。エンジン上で膨大な数の対戦を行い、強化学習（PPO）で強くなりました。対戦相手は過去の自分の
各バージョンと固定の相手からなるリーグなので、1つの戦い方に偏りません。技を選ぶこのネットワークは、人間のプレイを真似るようには
一切学習していません。選択はモデル自身のものです。それを補助する2つの小さなモデルは、公開されているShowdownのリプレイで
人間の行動を予測するように学習しています（後述）。

**何を見ているか。** 対戦の場にいるプレイヤーが知り得ることすべて：両者のチームシート（オープンチームシートのルールではそのまま。
クローズドのルールでは、使用率データから推定した相手の型）、場の状態、両者の場と控えのポケモン、直近のターン。
これをTransformerネットワークが読み、すべての合法手を評価します：対象つきの技、交代、そのルールのギミック（メガシンカ、
Zワザ、ダイマックス、テラスタル）。2体目の行動は1体目の行動を踏まえて選ぶので、2体が連携します。

**1ターンの決め方。** ネットワークの第一候補をそのまま選ぶわけではありません。1ターン先まで探索します：有力な行動候補を、
人間がとりそうな返しの手と組み合わせて、エンジン上で少し先まで進め、最も崩れない行動を選びます。返しの手は、公開されている
Showdownのリプレイで人間の行動を予測するように学習した2つ目のモデルが出します。つまりボットは自分自身ではなく、
人間を相手に想定して計画を立てます。3つ目のモデルは、人間の相手がどの4体を選出するかを予測します。

**数字の意味。** このツールでの勝率は、モデルが*両方*のプレイヤーを操作した結果です。両者が上手く立ち回ったときにチームや選出が
どう噛み合うかの強い目安ですが、人間との対戦結果を保証するものではありません。モデルが上手く扱えるチームは、
あなたが使うより強く見えることもあり、その逆もあります。

モデルの中身、学習方法、弱点については[モデルカード](MODEL_CARD.md)（英語）をご覧ください。

## ツール

アプリを開いてタブを選んでください。どのツールも、チームはShowdownのエクスポートの貼り付け、ポケソルのテキスト、
[pokepast.es](https://pokepast.es)のリンク、または**仮想敵リスト**（後述）で入力できます。

**オープンチームシートはそのまま使えます。** 努力値はなくても大丈夫です：ツール、仮想敵リスト、練習相手はどれも、
技・持ち物・特性だけの貼り付けを受け付けます。配分のない型には、使用率データからそのポケモンで最も多い配分を
（貼り付けに性格があればその性格で）当てはめ、配分のある型はそのまま使います。公開チームシートのチームを貼ってすぐに
対戦させられます。実際の配分がわかれば、より正確になります。

| ツール | 内容 | 使いどころ |
|---|---|---|
| **チーム研究 → チーム診断** | 自分のチームを仮想敵の各チームと何戦も対戦させます：相手ごとのスコアと、相手ごとに有効な選出（どの4体、どの2体が初手、相手の選出予想）。 | 「大会に出せる仕上がりか」の確認、苦手な対面とその選出探し。選出表を印刷して自分の研究用に（印刷 / PDFで保存）。大会前の予習用で、対戦中に使うものではありません。 |
| **チーム研究 → 1体入れ替え** | チームの1体の代わりを試します。自分の候補でも使用率上位でも。チームの成績順に並べます。 | 弱い枠の改善、6体目探し。 |
| **対戦研究 → 対戦シミュレーション** | 2つのチームを対戦させます：勝敗、有効な選出と初手、1ターン目の動き。 | 特定の対面の対策。 |
| **対戦研究 → 選出テスト** | 選出と初手を指定した2チームで、ボットが1ターン目か対戦全体を何回か行います。 | 「この初手をあれに当てたらどうなる？」 |
| **対戦研究 → 仮想敵との連戦** | 仮想敵の各チームとBo3を行い、実際の対戦として再生できます。 | 数字だけでなく対戦内容を研究したいとき。 |
| **対戦研究 → 選出アドバイザー** | 2チームを入れると、選出と初手のプランが出ます：何を出すか、相手が何を出しそうか、どう動くか。 | 選出画面での判断。 |
| **対戦研究 → 局面検討** | 1つの対戦をターンごとに：ボットの見方を見ながら両者の行動を選び、すべての分岐を残せます。 | 展開の検討、「相手が交代していたら？」 |
| **リプレイ → リプレイ分析** | リプレイをターンごとに、モデルならどこで違う選択をしたか、各選択肢をどれくらいの確率で選んだかを表示します。「標準」と「精密」では毎ターンにボットの探索をかけて、どの選択が一番響いたか、勝敗のどれだけが運で決まったかを示します。リプレイのリンクやID、ダウンロードしたリプレイ、インストール先の `replays` フォルダーに入れたファイルを読めます。 | 自分の対戦の振り返り。 |
| **仮想敵リスト** | チームの組み合わせに名前をつけて保存します（例：大会で当たりそうな相手）。チームごとに当たる頻度の重みをつけられます。オープンチームシートだけで十分で、努力値は不要です。 | チーム診断、連戦、練習相手の「対戦相手」として。 |
| **練習相手** | 練習相手の操作パネル（後述）。 | 練習。 |

**高速モードと探索モード。** ほとんどのツールに高速モード（ネットワークの直感。何千戦もすぐに終わります）と探索モード
（ボットが実戦と同じく探索して対戦します。時間はかかりますが、接戦のマッチアップではより信頼できます）があります。
探索モードにはGPUが必要です。GPUがなければアプリがそう表示し、探索モードはオフで始まります。

## 練習相手（トレーニングバディ）

自分のPC上で動くShowdownサーバーで、ボットが練習相手になります。他の人からは見えず、参加もできません。
対応するすべてのルールで（GPUでもCPUでも）フルの探索を使い、VGCの標準タイマーで対戦します。

Reg M-Cはすぐに遊べます：チームを選ぶまでは、アプリに付属の**Default**リストにある地域大会優勝チーム3つからボットが使います。
このリストも他のリストと同じく編集・削除できます。

1. **設定** - アプリの **練習相手 → 練習の設定**：ローカルサーバーで使う名前、ボットが使うチームとそのルール（ルールごとに1チーム：
   Showdownのエクスポートの貼り付け（努力値はあってもなくても）、ポケソルのテキスト、pokepast.esのリンク、または毎戦重みに従って
   引く `bucket:<リスト名>`）、オープンかクローズドのチームシート。ルールごとに任意で**初手練習**：ボットが指定した2体を必ず初手に出し
   （裏の2体も指定）、1つの対面を練習できます。
2. **練習用ボットを開始** - ローカルサーバーとボットが起動します。
3. **対戦** - 練習相手のページの **Showdownを開く** でローカルのShowdownを専用ウィンドウで開き（Showdown公式のクライアントページなので
   インターネット接続が必要です）、同じ名前で **PracticeBot** に「... buddy」のルールで対戦を申し込みます。例：
   「[Gen 9 Champions] VGC 2026 Reg M-C buddy」（Bo1またはBo3）。
4. **振り返り** - すべての対戦が **最近の練習対戦** にページへのリンクつきで並びます：対戦全体をターンごとに、そして
   **リプレイ分析で開く** で、モデルならどこで違う選択をしたか、各選択肢をどれくらいの確率で選んだかを確認できます。

**コーチ。** 練習の設定で **コーチ** にチェックを入れると、ローカルサーバーでの自分の対戦中に、自分だけに見えるパネルで
毎ターンのボットの読みが表示されます：探索が勧める行動と、相手の行動の予想です。練習専用で、他の機能と同じく
Showdownの公式サーバーには一切接続しません。

普段のShowdownの名前を使うと、パスワードを聞かれます：Showdownのクライアントは、ローカルサーバーでも登録済みの名前を
本物のShowdownサーバーで確認するためです。未登録の名前ならパスワードは不要です。

**練習セッション。** 何戦かをまとめられます：練習相手のページで **セッションを開始**（自分の名前とセッション名）、対戦して、
**終了**。セッションのページには戦績、両者の初手とポケモン、各対戦へのリンクが表示されます。対戦は後からセッションに追加・除外でき、
終了したセッションの再開もできます。

## フェアプレー

openVGCengineは、自分のPC上での練習と研究のためのものです。このリリースには、Showdownのサーバーやラダーで対戦する手段は
**ありません**：

- 練習相手のクライアントは自分のPC上のサーバーにしか接続せず（他のアドレスは拒否します）、「... buddy」のルールでしか対戦しません。
  このルールは付属のサーバーにしか存在しません。
- クライアントは自分が何者かを名乗るので、改造して公開サーバーにつないでも簡単に見分けられます。

ボットにレート戦をさせるのはShowdownの規約違反です。絶対にやめてください。

## リリースパッケージのインストール

### Windows

**必要なもの：** Windows 10または11（64ビット）、約4 GBの空き容量、セットアップ中のインターネット接続。GPUがあると探索を使うツールが
大幅に速くなります：

| GPU | セットアップが入れるもの |
|---|---|
| NVIDIA（GTX 16xx / RTX 20xx以降） | CUDA版。RTX 50シリーズにはドライバー580以降が必要 |
| Intel Arc / Core Ultraのグラフィックス | Intel GPU版（実験的） |
| AMD Radeon | CPU版。RX 7000 / 9000シリーズとRyzen AIのグラフィックスは、AMD独自のGPU版を試せます（実験的：ダウンロード約4 GB、ディスク9 GB）。後述 |
| なし | CPU版：すべてのツールが動きますが、探索モードはかなり遅くなります |

**手順：**

1. [Releases](https://github.com/HibikiDev/openVGCengine/releases)ページから `openVGCengine-<version>-win64.zip` をダウンロードし、
   専用のフォルダーに展開します（例：`Documents\openVGCengine`）。
2. **`setup.cmd`** をダブルクリックします。そのフォルダーの中に専用のPythonとアプリに必要なものをすべて入れ（システム全体には何も
   入れません）、結果を確認して、スタートメニューに **openVGCengine** を追加します。NVIDIAのGPUがあると約2 GBをダウンロードします。
   発行元が不明という警告が出ることがあります（コード署名をしていないため）：*詳細情報 → 実行*。
3. スタートメニューから **openVGCengine** を起動します。

**起動しないとき：** フォルダーの `openVGCengine (console).cmd` を実行してください。同じことをエラーが見えるウィンドウつきで行います。
小さいCPU版（や別の版）を強制するには、セットアップの前に `OPENVGC_TORCH_BUILD=cpu`（`cu130`、`cu126`、`xpu`、`rocm`）を設定します。
アップデート後もこの選択は保たれます。AMDのGPU版は、フォルダーでコマンドプロンプトを開き `set OPENVGC_TORCH_BUILD=rocm` を実行してから
`setup.cmd` を実行します。カードで動かない場合、セットアップはCPU版に戻ります。

**アップデート：** *このアプリについて・アップデート*（各ページの一番下）→ *アップデートを確認*。新しいバージョンがあれば
*アップデートをダウンロード*、次に *再起動してアップデート*。アプリが閉じ、自動でアップデートして再び開きます。仮想敵リスト、
実行結果、練習対戦はそのまま残り、何か問題があれば元のバージョンに戻ります。

手動でアップデートする場合：新しいzipをダウンロードして古いフォルダーの上に展開し（仮想敵リストと実行結果は残ります）、
もう一度 `setup.cmd` を実行します。

**アンインストール：** フォルダーの **`uninstall.cmd`** をダブルクリックします。確認のあと、アプリを止め、スタートメニューの項目を削除し、
フォルダーを削除します。仮想敵リスト、保存した実行結果、練習対戦も消えます。アプリのウィンドウ設定を置くユーザーフォルダーの
小さな `.openvgcengine` フォルダーも削除します。PCのそれ以外の部分は変更しません。

### macOS

**必要なもの：** Appleシリコン（M1以降）のMacと、セットアップ中のインターネット接続（約150 MB）。Intel Macには対応していません：
アプリが必要とするバージョンのPyTorchにIntel Mac版がないためです。探索を使うツールはMacのGPUを使います。

**手順：**

1. [Releases](https://github.com/HibikiDev/openVGCengine/releases)ページから `openVGCengine-<version>-macos-arm64.zip` をダウンロードして
   展開し、フォルダーを置いておく場所に移します（例：書類）。セットアップ後にフォルダーを移動すると、インストールしたPythonが壊れます。
   移動した場合はセットアップをもう一度実行してください。
2. セットアップを一度実行します。すべてをそのフォルダーの中に入れ、システム全体には何も入れません。アプリはまだAppleの署名を
   受けていないため、初回起動はmacOSにブロックされます。どのmacOSでも使える一番簡単な方法：ターミナル（アプリケーション →
   ユーティリティ）を開き、`bash` とスペースを入力して、フォルダーの **`setup.command`** をターミナルのウィンドウにドラッグし、
   Returnを押します。
   またはダブルクリックし、macOS 15以降は *システム設定 → プライバシーとセキュリティ → このまま開く*、macOS 14以前は
   右クリック → *開く*。
3. **`openVGCengine.command`** をダブルクリックしてアプリを起動します。ターミナルのウィンドウにアプリのログが表示されます：
   アプリを使っている間は開いたままにしてください。閉じるとアプリも終了します。ヒント：ファイルをDockにドラッグしておくと便利です。

フォルダーの `START HERE (Mac).txt`（英語）にも同じ手順があります。

**起動しないとき：** ターミナルのウィンドウの文字が手がかりになるので、不具合報告にコピーしてください。

**アップデート：** *このアプリについて・アップデート*（各ページの一番下）→ *アップデートを確認*。新しいバージョンがあれば
*アップデートをダウンロード*、次に *再起動してアップデート*。アプリが閉じ、自動でアップデートして再び開きます。仮想敵リスト、
実行結果、練習対戦はそのまま残り、何か問題があれば元のバージョンに戻ります。

手動でアップデートする場合：新しいzipを別の場所に展開し、ターミナルで `ditto` を使って古いフォルダーに統合します（`ditto` とスペースを
入力し、新しいフォルダー、古いフォルダーの順にドラッグしてReturn）。Finderでフォルダーを置き換えないでください：仮想敵リストと
実行結果が消えます。そのあと `setup.command` をもう一度実行します。

**アンインストール：** フォルダーをゴミ箱にドラッグします。仮想敵リスト、保存した実行結果、練習対戦も含まれます。アプリのウィンドウは
ホームフォルダーの隠しフォルダー `.openvgcengine` にも設定を置いているので、これも削除できます。Macのそれ以外の部分は変更しません。

### Linux

今のところソースからビルドしてください（後述）。パッケージは予定しています。

## ソースからのビルド

**必要なもの：** git、Python 3.13、Rust（`rust-toolchain.toml` のバージョン。[rustup](https://rustup.rs)が自動で選びます）、
Node.js 22.18以降（エンジンのデータ生成、チームの検証、練習相手のサーバーで使います）、bash（WindowsではGit Bash）。

```sh
git clone https://github.com/HibikiDev/openVGCengine
cd openVGCengine

# 1. エンジンが移植しているバージョンのShowdown（vendor/ - このリポジトリには含まれません）
git clone https://github.com/smogon/pokemon-showdown vendor/pokemon-showdown
git -C vendor/pokemon-showdown checkout 3661ce40bf9001d185ce078b8920e12304204609     # SHOWDOWN_PIN.md
(cd vendor/pokemon-showdown && npm ci --omit=dev && node build)

# 2. Python：まずGPUに合ったPyTorch（下の表。ここではCUDA 13.0）、次に残り
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install torch==2.14.0 --index-url https://download.pytorch.org/whl/cu130
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"   # 例: 2.14.0+cu130 True
pip install -r requirements/app.txt                      # numpy, jinja2, websockets, pywebview（torchは導入済み）
pip install -r requirements/dev.txt                      # maturin, pytest

# 3. エンジン（maturinでビルドするPython拡張）
(cd crates/engine-py && maturin build --release -o ../../target/wheels)
pip install target/wheels/vgc_engine-*.whl

# 4. モデル：Releasesページのmodels zipをここに展開します（models/ と、クローズドシートの型データが入ります。suite/pins.json が
#    models/ を参照します。型データがないと、ボットはクローズドシートのルール（VGC 2013〜2022）をネットワークだけで対戦します）

# 5. 練習相手のローカルShowdownサーバー（buddyルールのみ、127.0.0.1のみ）
bash tools/buddy/make_server.sh vendor/pokemon-showdown trainer/runs/buddy_server

# 6. 起動
python suite/web/app.py            # デスクトップのウィンドウ
python suite/web/server.py         # またはブラウザで http://127.0.0.1:8765
```

**どのPyTorchを入れるか**（手順2の `--index-url`。Windowsパッケージのセットアップも同じ基準で選びます）：

| GPU | インデックス | 備考 |
|---|---|---|
| NVIDIA、ドライバー580以降（`nvidia-smi` で確認） | `.../whl/cu130` | RTX 20xx〜50xx |
| NVIDIA、古いドライバー | `.../whl/cu126` | RTX 50シリーズは不可。ドライバーを更新してください |
| Intel Arc / Core Ultraのグラフィックス | `.../whl/xpu` | 実験的（fp32） |
| LinuxのAMD Radeon | `.../whl/rocm7.2` | 実験的。`cuda` と表示されます |
| WindowsのAMD（RX 7000 / 9000、Ryzen AI） | AMD独自のインデックス：`pip install "torch[device-all]==2.14.0+rocm10.1.0" --index-url https://stable.repo.amd.com/rocm/whl-next/` | 実験的、Radeonでは未検証。`cuda` と表示されます |
| Windowsのそれ以外のAMD、またはGPUなし | `.../whl/cpu` | すべてのツールが動きますが、探索モードはかなり遅くなります |
| macOS | なし：`pip install torch==2.14.0` | MPS経由でAppleのGPUを使います |

確認の行は、NVIDIAかAMDの版なら `True` と表示されるはずです（Intelは `torch.xpu.is_available()`）。アプリは使うデバイスを自分で選び
（CUDA、Intel、Apple、CPUの順）、CPUで動いているときはページにそう表示します。

Linuxでは、デスクトップのウィンドウにpywebviewのGUIバックエンドが必要です（`pip install "pywebview[qt]"`）。ない場合は `server.py` を使ってください。

**エンジンをShowdownと照合する：** `bash tools/diff/scripts/verify.sh <tag>` は回帰テスト用の対戦集と1,000戦のランダム対戦を両方の
シミュレーターで再生し、すべてのステップを比較します（エンジンの変更のたびに通している確認と同じものです）。

## ポケモンのアイコン（任意）

ページでは各ポケモンの名前の横に小さなアイコンを表示できます。アイコンは同梱していないので、ご自身で画像を用意してください。
インストール先の **`sprites`** フォルダー（ソースからの場合はリポジトリ直下の `sprites/`。gitの対象外）に、ポケモンの名前を
ファイル名にして入れます：`charizard.png`、`Charizard-Mega-X.png`、Showdownのスプライト名 `charizard-megax.png`、図鑑番号と
フォルムの語 `0006-Mega_X.png` など。詳しくはフォルダーの `README.txt`（英語）を見てください。画像がなければ名前だけを表示します。
アイコンがPCの外に出ることはありません。
